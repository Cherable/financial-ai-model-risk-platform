# A2 固定版本模型包

本目录只存放项目受控训练脚本生成的合成数据演示模型。当前版本为 `credit-logreg-v1` 和 `credit-logreg-v2`；开发登记清单为 [trusted_registry.json](trusted_registry.json)。模型包和登记清单都必须来自已检查的项目版本。

## 文件组成

每个版本均包含以下十个载荷文件和一个 manifest：

- `pipeline.joblib`：整体保存 SimpleImputer、StandardScaler 与 LogisticRegression；不能只保存分类器后另拟合预处理。
- `feature_schema.json`：固定六个特征及顺序、单位、范围、缺失规则和排除列。
- `training_config.json`：固定随机种子、C、阈值、训练参数、源数据摘要和实现代码摘要。
- `environment.json`：Python、系统、架构与依赖版本，用于加载前严格检查。
- `requirements.lock.txt`：该模型运行依赖的固定版本。
- `reference_distribution.json`：参考样本的固定特征分箱、预测概率分箱与缺失分箱；供 A4 使用。
- `explanation_config.json`：解释公式、基线、前三因素和 log-odds 单位。
- `model_parameters.json`：可读的中位数、均值、标准差、系数、截距与迭代次数。
- `evaluation.json`：仅使用 1,000 条留出合成测试数据的评估结果。
- `smoke_cases.json`：三个正常输入、一个收入缺失输入、一个全缺失输入的固定预期。
- `manifest.json`：版本身份、包格式和上述十个文件的 SHA-256。

manifest 自身的摘要保存在包外的开发登记清单；接入数据库后由 B 保存到受控版本元数据中，不能从客户端提供的 manifest 直接“自证可信”。

## 两个版本的目的

- v1 固定 C=1.0，v2 固定 C=0.5；两者阈值均为 0.5，种子均为 20261104。
- 两个配置在评估前确定，只用于展示版本固定与历史复现，不根据留出集挑选所谓最佳版本。
- 两个版本保留独立的模型文件、分箱、参数和解释；加载 v2 不会覆盖 v1。
- 训练脚本拒绝覆盖已有目录。修改配方或环境后请使用新版本名，不能重写已发布版本。

## 环境与完整性边界

当前包在 CPython 3.12.14、Windows AMD64、锁文件中的依赖组合下训练验证。加载器对这些环境字段精确比较；不匹配时先恢复匹配环境，或在自己的环境使用新版本名重训，再登记新摘要。不要通过删除检查来“兼容”模型。

加载顺序是：验证版本名与受控路径 → 检查可信 manifest 摘要 → 检查全部载荷摘要 → 核对环境与特征模式 → 最后加载 joblib。未知版本、缺文件或不匹配均直接失败，不回退到当前模型。

joblib 属于 pickle 系列，加载不可信文件可能执行代码。SHA-256 只能验证相对于已批准摘要的完整性，不能提供数字签名，也不能阻止有权限同时修改模型与登记清单的人。只允许开发人员登记本项目自产、已检查的包，不能给 HTTP 客户端提供任意上传后反序列化的能力。[scikit-learn 官方模型持久化说明](https://scikit-learn.org/stable/model_persistence.html)

## 复现和解释

保存后的包已在独立进程加载，两个版本各五条验收样例均通过，最大概率误差为 0。跨机器浮点完全一致不能无条件保证；正式验收口径仍为误差不超过 1e-8 且阈值判断一致。

解释使用标准化后的值乘以系数，全部贡献与截距相加后经 sigmoid 应还原评分。前三因素按贡献绝对值选取；正贡献提高相对于标准化零向量的 log-odds，负贡献降低。它们不是概率百分点，也不是因果结论。

源数据、模型和评估都是教学模拟结果；生成式 AI、真实客户审批和生产风控不在本次交付范围。
