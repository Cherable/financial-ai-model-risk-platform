# 数据与接口约定

本文件是双方协作契约。A3 已实现评分、激活和原子留痕，详细请求与状态语义见 [A3 接口操作与交接](A3-接口操作与交接.md)；其余功能仍是待实现设计，变更时同步调用方、存储和验收案例。

## 1 统一约定

- API 路径前缀 `/api/v1`，JSON 使用 snake_case，编号使用 UUID 字符串。
- 内部时间统一为带 `Z` 的 UTC ISO 8601；页面显示北京时间 UTC+8，并标明时区。
- 概率与统计使用双精度计算，保留原始精度；页面可以格式化但不能用页面舍入值做复现比较。
- 贷款金额、月收入的请求传十进制字符串，数据库以整数分保存；模型转换为元时按固定预处理执行。金额字段不能使用二进制浮点做账务求和。
- 请求身份来自令牌，不接受客户端传来的角色或用户编号作为授权依据。
- 请求携带 `Idempotency-Key`；同一调用主体、接口与键唯一。同键且请求体摘要相同返回原记录；同键但内容不同返回 409。
- 原始输入与规范化后的模型输入分别保存，缺失值不得在保存原始快照前被静默覆盖。
- A3 评分请求为 `{"model_version_id":"UUID","input":{六个特征与可选customer_ref}}`；幂等摘要保留原始内容差异，忽略 JSON 对象键顺序。

## 2 评分特征字典

- `customer_ref`：虚构客户编号，字符串，不含身份证或手机号；不参与模型计算。
- `age`：整数，单位岁，演示范围 18—80，可为 null；越界返回 422。
- `monthly_income`：十进制字符串，单位元，范围 0—1,000,000，可为 null；负值拒绝。
- `debt_income_ratio`：数值，单位比例，演示范围 0—3，可为 null。
- `past_due_count`：整数，单位次，范围 0—100，可为 null。
- `loan_amount`：十进制字符串，单位元，范围大于 0 且不超过 10,000,000，可为 null。
- `employment_years`：数值，单位年，范围 0—60，可为 null；训练与推理采用相同单位。

缺失字段统一规范化为 null 并保留缺失掩码；范围校验失败不进入模型。缺失可由 Pipeline 填补，但仍计入缺失率。字段范围是演示约束，不代表实际信贷业务规则。

## 3 核心实体与约束

### 模型与版本

`models`：`model_id`、名称、用途、创建者、创建时间。

`model_versions`：`model_version_id`、`model_id`、版本号、状态、模型包引用、包文件清单与 SHA-256、特征模式版本、依赖锁引用、训练配置、随机种子、决策阈值、解释基线与参考分布引用。

约束：同一模型版本号唯一；历史版本不可覆盖；可选激活指针由受控事务切换；删除被评分引用的版本应拒绝。模型包在磁盘采用版本目录，数据库维护元数据。

### 评分与证据

`predictions`：`prediction_id`、幂等键、请求摘要、调用主体、模型版本、受理时间、完成时间、状态、概率、阈值判断、推理耗时、错误码、输入快照引用、解释快照。

`input_snapshots`：`snapshot_id`、原始 JSON、规范化模型输入、字段模式版本、内容摘要；只保存合成演示数据，普通列表不返回完整快照。

成功记录概率非空，范围为 0—1；失败记录概率必须为空。请求重复不能新增快照或评分。成功记录必须关联有效版本与输入。

### 监测与告警

`monitor_rules`：规则编号、版本、模型版本、指标名、阈值、最小样本数、生效时间、创建者。

`monitor_windows`：模型版本、窗口起止、总事件数、成功数、失败数、缺失计数和分箱计数；按版本与窗口唯一。

`metrics`：指标编号、模型版本、窗口、指标名、特征名、值、有效样本数、参考版本、计算版本。按上述业务维度设唯一约束；无结果时记录明确状态，不写伪造零值。

`alerts`：告警编号、模型版本、窗口、规则版本、指标、触发值、级别、状态、处理人、处置说明、创建和关闭时间。同一指标与窗口、规则版本只触发一条逻辑告警。

`alert_actions`：告警编号、操作类型、操作者、前后状态、说明与时间。保留完整处置历史。

### 审计、权限与复现

`users`、`roles`、`user_roles`、`model_access`：用户、角色、角色关联、模型授权。密码保存哈希；角色和模型范围都由服务端核对。

`audit_logs`：审计编号、操作者、动作、资源类型及编号、时间、关联请求、结果、必要的变更摘要。禁止记录密码或 JWT。

`replay_runs`：复现编号、原评分编号、版本、环境核验、原概率、新概率、绝对误差、判断是否一致、状态、失败原因、操作者与时间。

基础版以应用权限和只追加业务操作限制修改历史记录，不声称能抵御数据库管理员篡改。哈希链和外部锚定可作为扩展设计。

### 可靠事件

`outbox_events`：`event_id`、`prediction_id`、事件类型、schema 版本、负载、创建时间、状态、尝试次数、下次尝试时间、租约过期时间、最后错误。

`processed_events`：消费者名称与 `event_id` 联合唯一，记录完成时间。单 worker 消费；领取后崩溃可在租约到期后重试。若同一事务写入标记和聚合结果，则重复事件不会重复累计。

## 4 状态机

- 模型版本：`registered → validated → active → archived`；未验证版本不得激活，归档不删除历史包。
- A3 实现补充：版本就绪状态保留 validated，active 由每个模型的独立激活指针表示；切换指针不覆盖历史包。未激活旧版本不能接受新评分，但历史幂等请求仍可重放。
- 评分记录：`success` 或 `failed` 为终态；请求格式错误为 422，不创建伪造评分，可另记拒绝日志。
- outbox：`pending → processing → done`；可重试失败回到 pending，超过五次进入 `dead_letter`；processing 租约到期可重新领取。
- 告警：`open → acknowledged → closed`；关闭必须填说明，基础版不实现自动重开。需要新处置时追加动作而不是覆盖历史。
- 复现：`pending → running → passed/mismatch/failed`。mismatch 是计算成功但结果不一致，failed 是无法完成计算。

## 5 监测计算口径

固定 60 秒非重叠窗口，范围 `[start, end)`；归属按服务器请求受理时间，避免客户端时钟影响。以请求完成后落库的事件更新窗口；窗口结束后预留十秒迟到宽限再计算。超过宽限才恢复的事件应对原窗口重算并保留修订编号，而不是丢弃。

规则按窗口起点选择已生效版本，不在同一窗口中途切换；重算仍使用该窗口原规则版本。告警唯一键不因重算改变，追加修订记录。

- 缺失率：某字段缺失的成功评分条数 / 成功评分总数。另列评分失败率，不能混用分母。
- 失败率：推理失败次数 / 已完成推理尝试总次数；不含 422 校验拒绝、入库失败和 inference_attempted=false 的模型加载失败。请求服务错误率另按 API 日志统计。
- 推理耗时：只计模型 Pipeline 调用时间；P95 使用成功样本。端到端 API 时延另测，不能用推理耗时代替。
- PSI：参考样本固定分箱，参考占比为 `p_i`、当前占比为 `q_i`，计算 `Σ(q_i-p_i)×ln(q_i/p_i)`。占比为零时采用固定 epsilon 平滑后归一化，保存 epsilon 和计算版本；参考边界覆盖极端值，缺失采用独立分箱。
- 漂移指标：单个特征 PSI 和预测概率 PSI 分开记录；样本不足 200 时显示 `insufficient_samples`，不触发 PSI 告警。
- 建议演示阈值：字段缺失率大于 5%、PSI 大于 0.2、失败率大于 1%。这些是预设演示参数，需结合模拟数据校准，不是行业统一标准。

没有真实结果标签时，只能报告数据、预测分布和运行质量变化，不能计算实时准确率、AUC 或认定效果退化。扩展标签回流需记录标签定义与观察期，样本不足或仅有单一类别时不输出误导性 AUC。

## 6 接口清单与归属

接口均在 `/api/v1` 下，除健康检查外都需要身份认证与模型范围授权。

- B：`POST /auth/token`，验证凭据并返回令牌；登录凭据不写日志。
- A：`POST /models`，创建模型；`POST /models/{model_id}/versions`，登记受控模型包。
- A：`POST /model-versions/{version_id}/activate`，管理员激活已验证版本并审计。
- A：`POST /predictions`，对明确的版本执行模拟评分并原子留痕；禁止在请求处理中混用版本。
- A：`GET /metrics`，按模型、版本、指标和窗口查询；返回状态、样本数和单位。
- A：`POST /monitor-rules`，创建新规则版本；历史规则不就地覆盖。
- A：`GET /alerts`，分页查询；`POST /alerts/{alert_id}/acknowledge`、`POST /alerts/{alert_id}/close`，执行状态变化。
- B：`GET /predictions/{prediction_id}`，读取评分证据；A 的页面可复用。
- B：`GET /audit/records`，分页查询；`GET /audit/records/{prediction_id}/export`，生成授权范围内的报告并记录导出动作。
- B 主责、A 配合：`POST /replay-runs`，传原评分编号并创建任务；`GET /replay-runs/{replay_id}`，查询结果。复现任务与监测事件分开定义类型，由同一基础版单 worker 分派处理。
- B：`GET /health`，报告 API 与数据库状态；受限运维接口提供 worker 心跳与积压。

分页建议默认 20、最多 100；查询时间范围需有限制。错误采用 401 未登录、403 无权限、404 不存在、409 幂等冲突或状态冲突、422 参数错误、503 临时依赖故障；具体数据库异常不直接泄漏给客户端。

## 7 评分事件样例

以下编号是虚构示例，模型版本必须在数据库存在；该示例是 outbox 内部负载，不是客户端请求体。它与评分、快照同事务生成。

```json
{
  "schema_version": "1.1",
  "event_id": "00000000-0000-4000-8000-000000000001",
  "event_type": "prediction.completed",
  "prediction_id": "00000000-0000-4000-8000-000000000002",
  "model_version_id": "00000000-0000-4000-8000-000000000003",
  "request_received_at": "2026-11-04T02:00:00Z",
  "completed_at": "2026-11-04T02:00:00.035Z",
  "status": "success",
  "risk_probability": 0.173512,
  "decision_threshold": 0.5,
  "decision": "below_threshold",
  "inference_ms": 4.8,
  "inference_attempted": true,
  "error_code": null,
  "snapshot_id": "00000000-0000-4000-8000-000000000004"
}
```

事件不复制完整输入，由 worker 按授权服务路径读取快照；失败事件保留错误分类，概率、阈值判断置 null。事件编号全局唯一，评分编号与版本编号用于审计关联，三者不能互相代替。

schema 1.1 增加 inference_attempted 与 error_code；加载阶段失败没有执行推理，因此 inference_ms 为 null。A3 当前只保存 pending 事件，消费与监测由 A4 实现。

## 8 事务与复现边界

评分链路：鉴权与校验 → 固定版本推理 → 在同一事务保存输入快照、评分、初始审计证据和 outbox → 提交后响应。推理在事务外执行，避免长时间占用 SQLite 写锁。

worker 停止不会阻止评分事务继续提交；数据库不可写时返回失败，不承诺评分成功，不能同时声称“审计数据必不丢”和“数据库故障仍无条件返回成功”。

历史复现需固定：模型包、预处理 Pipeline、特征模式与顺序、依赖环境、输入、阈值和解释配置。基础版以概率绝对误差不超过 `1e-8` 且阈值判断一致为通过条件；环境不一致先失败并提示，不把不一致结果标记为通过。
