# A1 监测需求与用例

本文件交付成员 A 第一项任务的需求部分，用于后续需求说明书和报告第二章。这里描述的业务接口仍待 A2—A5 与成员 B 实现；当前已经可运行的是合成数据生成与校验工具。

## 1 范围与参与者

目标业务链路：登记固定模型版本 → 合法请求评分并留痕 → 后台按窗口计算指标 → 规则触发告警 → 人工处置 → 审计追溯。

模型开发人员负责登记；管理员负责激活；模拟评分调用方提交虚构特征；风险人员查询指标、维护规则和处置告警；审计人员只读查询相关证据。角色与模型范围双重授权由 B 提供。

监测输入仅为服务器保存的评分事件与原始输入快照。参考样本用于固定分箱，训练集用于拟合，测试集用于一次留出评估，三者不得交换用途。

## 2 UC-A01 模型登记与验证

参与者：模型开发人员，管理员。

前置条件：已登录且有该模型的登记权限；模型文件由受控脚本产生，位于服务器受控模型目录；不能接受客户端任意磁盘路径或网络下载地址。

输入：模型名称、用途、版本号、模型包受控引用、文件摘要、特征模式、Pipeline 与依赖版本、阈值、训练与参考数据摘要、解释配置。

处理：

1. 校验身份、模型范围和版本号唯一性。
2. 核对文件清单、摘要及特征模式，检查参考数据来源。
3. 使用固定样例验证输入输出格式；这不等于生产风险验证。
4. 保存 registered 版本，验证通过后转 validated；由管理员单独执行激活并审计。

输出：模型编号、版本编号、验证结果及状态；同一版本禁止覆盖。

异常：无权限 403；版本冲突 409；参数不完整 422；受控包不存在或不兼容时保留明确失败原因，禁止激活。模型包不存在与接口资源不存在应由后续错误码契约区分。

验收：两个不同版本可同时登记；未验证版本不能激活；激活不会删除旧包；审计能查到操作者与变更。

## 3 UC-A02 模拟评分与监测事件产生

参与者：获授权的模拟评分调用方。

前置条件：明确选择已允许评分的固定版本；模型包和存储可用；请求携带幂等键。

输入：虚构 customer_ref、六个特征、model_version_id；金额为两位小数的十进制字符串。标签、模拟数据所属集合、生成概率等不得进入评分特征。

处理：

1. 校验身份、模型范围、字段类型和范围；缺失规范化为 null。
2. 检查幂等键与请求摘要，固定本次版本。
3. 保存原始缺失信息后，通过原 Pipeline 填补、变换和推理，计时与解释。
4. 调用 B 的统一存储事务保存快照、评分、初始审计和 outbox。
5. 提交成功后返回，监测不在请求中同步计算。

输出：prediction_id、版本、状态、概率、阈值判断、解释与时间。推理失败时概率为 null；不得用 0 表示失败。

异常：参数错误 422；同键异内容 409；模型暂时不可用或数据库不可写按接口约定返回 503/明确失败；数据库无法写入时不能声称已完整留痕。相同成功请求重试返回原记录，不重复计数。

验收：正常输入可关联完整证据；缺失收入仍可被预处理但计入缺失率；在线 CSV 空字段在请求组装时转 null，不能发送空字符串冒充数值。

## 4 UC-A03 指标计算与查询

参与者：后台 worker、模型开发人员、风险人员。

前置条件：存在评分事件与固定版本参考分布；worker 可连接数据库。查询角色只能读取授权模型。

输入：模型版本、窗口范围、指标名称、参考分布版本、评分状态及缺失掩码。

处理：

1. 按服务器受理时间划分 60 秒非重叠窗口 `[start,end)`，预留十秒迟到宽限。
2. 聚合成功/失败计数、缺失计数和分箱计数；聚合与消费标记保持幂等。
3. 计算缺失率、特征 PSI、概率 PSI、失败率与推理耗时 P95。
4. 漂移有效样本小于 200 时返回 insufficient_samples；分母为零时返回 no_data，不伪造零指标。
5. 保存样本数、单位、分箱/计算版本；迟到事件按原规则重算并保留修订信息。

输出：模型与版本、窗口、指标、值或不可计算状态、分子分母或样本数、参考版本、更新时间。查询默认分页 20，最多 100。

异常：worker 暂停时显示心跳和积压状态，不能把旧指标标记为实时；参考分布缺失时标为计算失败；零占比分箱使用固定 epsilon 平滑并归一化。

验收：手工构造十条样本其中一条缺失，缺失率应为 10%；样本不足时不生成 PSI 告警；重放事件不增加统计。上述业务验收尚待 worker 实现。

## 5 UC-A04 规则创建与版本变更

参与者：有规则管理权限的风险人员。

前置条件：模型版本存在，指标名有效。

输入：指标/特征、比较符、阈值、最小样本量、生效时间、变更理由。

处理：校验阈值合法性；创建新规则版本；窗口按起点匹配生效规则；保留历史规则并写审计。比例阈值范围 0—1、PSI 非负、耗时单位毫秒；不将不同单位的数值混用。

输出：规则编号、版本、参数和生效时间。

异常：无权限 403；参数或单位错误 422；冲突变更返回 409。已有规则不得原地覆盖导致旧告警失去依据。

验收：新阈值只影响后续生效窗口；旧窗口修订仍使用原规则版本；修改人、理由和前后版本可查询。

## 6 UC-A05 告警生成与人工处置

参与者：后台 worker、风险人员、只读审计人员。

前置条件：窗口有足够数据，存在生效规则；处置者具备该模型授权。

输入：指标值和规则；人工处置时输入 alert_id、目标状态、原因与结论。

处理：

1. 达到规则条件后创建 open 告警；按模型版本、窗口、指标与规则版本唯一去重。
2. 风险人员认领，状态改为 acknowledged，追加操作记录。
3. 确认原因后填写说明并关闭；不得直接修改历史触发值。
4. 审计查询可关联指标、原规则、相关评分及全部处置动作。

输出：告警编号、状态、触发值/阈值、窗口、样本数、责任人和处置记录。

异常：无权限 403；状态冲突 409；关闭说明缺失 422；写失败回滚状态与处置动作。事件重试不重复创建告警。

验收：重复事件不重复告警；未认领不能直接走基础版关闭流程；关闭后仍能查到原触发依据。

## 7 数据与运行质量需求

- REQ-A01：监测必须按模型版本隔离，不能把两个不同版本的分布混合。
- REQ-A02：每条评分必须保留原始输入缺失信息，不能只监测填补后的“全非空”矩阵。
- REQ-A03：漂移与模型效果分开表达；缺失真实标签时不得显示实时准确率或 AUC。
- REQ-A04：暂停监测进程不阻断数据库可用时的评分保存；恢复后能补算。
- REQ-A05：所有查询显示窗口和样本数；异常状态清晰，不用旧值代替当前值。
- REQ-A06：来源数据、分箱边界、规则和计算过程都可版本化追溯。
- REQ-A07：测试集不得参与预处理拟合或阈值调优；customer_ref 和标签不进入特征列表。

质量属性的可量化目标和后续测量方式沿用 [ASR 与验收方案](05-ASR与验收方案.md)。本次不提前声明 API、监测和权限验证已通过。

## 8 数据流与交接

P1 模型登记读写模型元数据及模型包引用；P2 评分写评分证据和 outbox；P3 消费事件并读取原始快照、参考分布和规则，写指标和告警；P4 人工处置追加告警动作；B 的 P5 审计与复现读取证据与历史版本。

交给 B 的已完成材料：本需求文件、六组 CSV、manifest、字段与缺失说明、独立校验结果、十条待人工核验样本。B 后续提供的数据库事务、鉴权和 API 尚未由本次代为实现。

本次 A1 不引入大模型 API；未来若增加智能摘要，应作为独立扩展需求，不改变这里的确定性监测指标和历史证据。
