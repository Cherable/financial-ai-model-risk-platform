# 双人分工与实施步骤

## 1 分工原则

A 负责模型与监测，B 负责审计与平台基础。双方各自完成需求、设计、页面与验证，不按“一个人写代码、另一个人写报告”划分。A1—A5 已交付数据、模型、评分、独立监测、告警后端及三个页面；当前使用 SQLite 与演示认证适配器，B 的正式平台集成仍待完成。

A 的算法、样本与 worker 工作较多，主笔两类架构图；B 的数据库、权限与部署工作较多，主笔三类架构图。贡献评价按实际交付、集成记录和问题修复记录说明，不预先虚构排名。

## 2 成员 A 的任务

### A1 明确监测需求和准备数据

操作：列出模型登记、评分、指标查询、规则配置、告警处置用例；每个用例补充参与者、前置条件、输入、处理、输出和异常。使用 Python 生成训练、测试、参考和三类评分流，固定种子并检查范围与缺失比例。

交付：监测需求小节、数据说明、`scripts/generate_data.py`、合成 CSV。

当前状态：需求、脚本和数据已完成，见 [A1 交接记录](A1-完成记录与交接清单.md)；自动化验收通过，B 的人工抽查待执行。

验收：B 随机抽查十条数据，能解释每个字段；相同参数重生成内容一致；训练与测试样本不混用。

### A2 建立可复现模型包

操作：使用 SimpleImputer、StandardScaler 和 LogisticRegression 构成 Pipeline；训练时固定随机参数。把 Pipeline、特征模式、阈值、参考分布、依赖清单和训练配置关联到不可覆盖的版本目录。

简单解释采用标准化特征的逻辑回归系数贡献 `coefficient × transformed_feature`，按绝对值选取前三项，并说明贡献处于 log-odds 空间、不是因果解释。原评分时保存解释快照。

交付：`app/modules/models/`、`app/modules/scoring/`、`artifacts/<version>/`，以及模型说明。

当前状态：上述模块与两个版本已完成，见 [A2 交接记录](A2-完成记录与交接清单.md)；17 项 A2 测试及两版各五条独立进程加载样例通过，B 的人工交接待执行。

验收：B 在相同环境中加载受控文件，用约定输入得到一致结果；模型文件变动能被摘要检查发现。

### A3 完成评分接口与可靠事件交接

操作：通过存储适配器在一个事务中保存评分、审计证据和 outbox，相同幂等键获取原回执。A 已提供 SQLite 参考实现和替换契约，B 接手后完成正式平台适配。模型异常记录失败类别与耗时。

交付：评分接口、模型激活接口、正常与失败记录样例。

当前状态：接口、原子留痕、幂等和样例已完成，见 [A3 操作与交接](A3-接口操作与交接.md)。B 尚未提供实际服务，本次定义替换契约并使用参考适配器；自动化验证通过，B 联调待执行。

验收：A、B 一起验证同一个事件提交两次只有一条逻辑记录；保存失败时不返回成功。

### A4 编写监测 worker

操作：从数据库领取待处理事件，使用单 worker、短事务和可恢复租约；按固定窗口聚合计数。计算过程与评分请求分离；写入消费标记、窗口统计、指标和告警时采用事务与唯一约束。

未满窗口先显示待完成状态；样本过少不计算漂移。恢复后补算，失败达到次数上限进入人工检查列表。

交付：`app/worker.py`、`app/modules/monitoring/`、`app/modules/alerts/`。

当前状态：上述模块与监测/告警接口已完成，见 [A4 运行与验收](A4-监测worker与验收.md)。覆盖去重、恢复、窗口指标、迟到修订、规则和人工处置；独立进程验证通过，真实时效和 B 适配器联调待完成。

验收：进程停止后评分仍能保存；重启后待处理事件补齐，指标和告警不重复。

### A5 完成页面与图文材料

操作：通过 API 实现模型版本页、监测页、告警页；展示窗口、样本数、规则版本和触发原因。绘制业务与逻辑架构图，主笔一级数据流图。

交付：`ui/pages/models.py`、`monitoring.py`、`alerts.py`，业务与逻辑架构图、一级数据流图、实际浏览器截图与验证记录。

当前状态：A5 已完成，见 [操作与交接](A5-页面操作与交接.md)；累计 108 项自动化测试通过。B 的正式身份与审计平台集成待执行。

## 3 成员 B 的任务

### B1 确定审计需求与数据库约束

操作：核对第 4 份文档与现有 SQLAlchemy 表结构，接手 `app/storage/sqlite_store.py` 和 `app/modules/monitoring/store.py`。补充数据字典、正式平台缺口和迁移，保留评分、快照、审计、outbox 及回执的事务关系。替换存储时同时提供监测适配器。

交付：数据字典、ER 图、兼容迁移与正式存储适配器。具体目录沿用现有模块边界，根据实际缺口组织代码。

当前状态：参考存储与初始化由 A 已交付，B 的审查、正式适配和旧库迁移验收待执行。

验收：A 用正常、失败、重复三类记录检查入库行为；外键启用，非法版本引用被拒绝。

### B2 实现身份和权限

操作：采用 Argon2 密码哈希和短期 JWT；准备四类测试账号；令牌只携带必要标识，模型授权从服务端检查。不同角色通过同一 API 权限层访问，不能仅在页面上隐藏按钮。

交付：正式认证器、用户初始化脚本、权限检查清单。

当前状态：演示 Bearer 认证及服务端角色与模型范围检查已可运行，B 的正式账号、密码哈希和 JWT 待实现。

验收：未登录返回 401；角色或模型范围不足返回 403；篡改角色参数不提升权限；日志与截图不出现密码、令牌或真实身份数据。

### B3 实现审计详情与导出

操作：按评分编号关联输入、版本、阈值、解释和后续处理；支持按模型、时间、结果分页检索。详情查询和导出均审计，禁止普通业务接口更新历史原始记录。

交付：`app/modules/audit/`、JSON/CSV 导出服务、审计页面。

当前状态：评分、激活、规则和告警动作已有持久记录，B 的审计查询、导出与页面待实现。

验收：能从一个编号找到完整证据；越权详情与导出均被阻止；导出内容与数据库记录一致。

### B4 与 A 合作实现复现

操作：B 负责检索快照、验证权限、组织复现任务和保存结果；A 负责固定版本加载与推理。原输入传给原 Pipeline，比较概率误差和最终阈值判断，不调用当前激活版本替代。

交付：`app/modules/replay/`、复现页面、缺文件与摘要异常案例。

当前状态：A2 固定版本加载和推理可复用，B 的任务组织、授权、结果持久化及复现页面待实现。

验收：版本切换后仍可复现旧记录；依赖不一致时明确报告；历史解释快照不因新模型覆盖。

### B5 完成环境、图文与集成

操作：维护安装和启动说明、环境变量模板、依赖锁文件；绘制数据、技术、部署图；负责报告版式汇总，A 负责检查其技术内容。

交付：审计与复现页面、正式平台配置、数据/技术/部署架构图、环境记录和报告合并稿。

当前状态：`app/config.py`、依赖锁和 A 的启动说明已交付，B 补充正式平台环境与部署并汇总双方报告。

验收：A 按文档在另一工作目录完成安装与启动；报告中的组件与代码、接口和部署一致。

## 4 必须先统一的接口

开始编码前共同冻结：评分请求与响应、事件字段、数据库命名、错误码、角色权限、UTC 时间格式、数值精度和模型包结构。

交接顺序：

1. A 交给 B：特征模式、两个模型版本、标准输入输出样例、失败分类和解释快照。
2. B 交给 A：评分持久化方法、outbox 数据结构、鉴权依赖、分页响应结构。
3. A 交给 B：告警与处置关联方式、指标窗口和规则版本编号。
4. B 交给 A：审计详情与复现结果接口，供告警页跳转。

接口变化先修改第 4 份文档，再同步双方实现。不要仅通过口头通知变更字段。

## 6 Git 与文件协作

已创建公开 GitHub 仓库 `Cherable/financial-ai-model-risk-platform`，存在 A、B 和 main 分支。当前 A1 至 A5 已发布到 A 分支，B 接手时先在自己的分支同步 A 的已完成基线，操作见第 7 份文档。

- A 使用 `A/model-monitoring` 分支，B 使用 `B/audit-platform` 分支。
- B 主改正式存储、鉴权、审计、复现和部署，A 主改模型、监测与告警。共享契约、应用工厂、元数据、配置和需求说明书随任务主责修改，并在交叉检查中核对。
- 各自先提交小块完整变化，再合并；不要用覆盖整个目录的方式交换代码。
- `.gitignore` 应排除虚拟环境、数据库运行文件、JWT 密钥、缓存和导出证据中的敏感内容；依赖锁文件、合成样例和设计文档应保留。
- 记录任务编号、提交或文档版本、完成者、检查者与证据路径，用于报告分工说明。

## 7 答辩分工

A 讲业务场景、数据与模型、监测算法、告警闭环、业务与逻辑架构；B 讲数据库、权限、审计复现、可靠事件机制、技术与部署架构。演示由 A 完成正常到告警，B 接续历史追溯与复现。

共同准备四个问题：为什么漂移不等于效果下降；为什么需要 outbox；为什么历史复现必须固定整个 Pipeline；SQLite 的并发限制何时需要升级数据库。
