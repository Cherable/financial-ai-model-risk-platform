# 软件环境与操作手册

## 1 技术选择

基础版采用 Python 为主的模块化应用，界面通过 HTTP 调后端，监测独立进程运行。这样两人可使用同一种语言，同时保留业务、逻辑和物理部署层次。

- Python 3.12：作为统一开发基线；选择官方支持且可获取的兼容安装包，不要求追逐最新大版本。两人必须使用相同小版本和锁定依赖。
- FastAPI 与 Uvicorn：定义接口、输入校验、认证依赖和接口文档。A、B 共同使用。
- Streamlit 与 Plotly：开发演示页面与趋势图。双方分别实现负责页面。
- SQLAlchemy 2 系列与 SQLite：管理关系数据、事务和查询；由 B 维护。SQLite 随 Python 提供，无需安装数据库服务。
- scikit-learn、pandas、NumPy、joblib：生成数据、训练与保存受控模型包、计算指标；由 A 维护。
- PyJWT 与 pwdlib/Argon2：令牌与密码哈希；由 B 维护。
- pytest 与 httpx：验证幂等、权限、复现、异常恢复与接口行为。
- Git：保存版本与集成；VS Code 的 Python 扩展或熟悉的 Python IDE 均可。
- diagrams.net：整理正式架构图、数据流图和 ER 图；保留可编辑源文件，导出 SVG 或清晰 PNG。
- Word 或能保持原模板格式的办公软件：最终报告排版与提交。不要直接改写原始模板。

建议设备：Windows 10/11、四核 CPU、8 GB 内存起、约 3 GB 可用空间；16 GB 内存更便于同时开 IDE 和办公软件。这是原型配置建议，不是实测最低要求。无需独立显卡。

## 2 可选软件

- DB Browser for SQLite：图形查看演示库。修改数据库结构时关闭工具连接，避免占用写锁；不要直接修改审计证据。
- Apifox 或 Postman：可选；FastAPI 的 `/docs` 已能完成基础接口调试。
- Docker Desktop：仅在需要容器演示时安装；Windows 系统要求和 WSL 设置按官方文档检查。基础版不依赖 Docker、Redis、Kafka 或云服务器。
- PostgreSQL：当验证目标转为多 worker、较高写并发或多机部署时再引入，并重新验证事务与锁行为。

## 3 安装顺序

1. 两人安装或确认已有 Python、Git、编辑器和办公软件。
2. 确认终端能调用指定 Python；VS Code 选择项目虚拟环境解释器。
3. 在双方约定的代码目录创建独立虚拟环境，安装直接依赖。
4. A 验证数据处理和训练依赖；B 验证 Web、认证和数据库依赖。
5. 一方生成锁文件，另一方在干净虚拟环境复装并验证后，共同确定环境基线。

当前操作仅编写文档，没有替用户安装上述软件。

## 4 Windows 环境检查与安装命令

以下命令由实施时在项目代码目录手工执行。除虚拟环境安装外，不需要管理员 PowerShell。创建后续代码目录时先确认位置，避免把虚拟环境放入系统目录。

```powershell
py --list
py -3.12 --version
git --version
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install fastapi uvicorn streamlit plotly sqlalchemy scikit-learn pandas numpy joblib pyjwt "pwdlib[argon2]" python-multipart pytest httpx
.\.venv\Scripts\python.exe -m pip check
```

无需激活脚本即可直接使用虚拟环境中的 Python，因此不必为本项目改变系统执行策略。如果没有 `py` 启动器，使用已安装 Python 的完整路径替代，并确认它确实是约定版本。

第一轮联调通过后，在专用虚拟环境中生成依赖快照：

```powershell
.\.venv\Scripts\python.exe -m pip freeze | Set-Content -Encoding utf8 requirements.lock.txt
```

另一台机器创建干净虚拟环境，使用：

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.lock.txt
.\.venv\Scripts\python.exe -m pip check
```

记录 Python、系统、NumPy、scikit-learn 等版本；锁文件固定项目依赖，但不是跨操作系统二进制完全可复现的保证。第一轮安装需要网络，演示时应预先完成安装，不现场更新包。

## 6 配置约定

由 B 实现 `app/config.py` 读取环境变量，并对缺失密钥、无效路径和不合理参数给出明确错误。环境变量至少包括：

```text
APP_ENV=development
DATABASE_URL=sqlite:///./data/platform.db
ARTIFACT_ROOT=./artifacts
API_BASE_URL=http://127.0.0.1:8000
JWT_SECRET=<由每台机器独立生成，不提交到仓库>
TOKEN_TTL_MINUTES=30
WORKER_POLL_SECONDS=5
MONITOR_WINDOW_SECONDS=60
MIN_DRIFT_SAMPLES=200
SQLITE_BUSY_TIMEOUT_MS=5000
```

这只是配置格式示意，`.env` 不会被 Python 自动读取；基础版统一在三个 PowerShell 终端设置所需环境变量，或由 B 显式实现文件加载并加入对应依赖。所有命令从代码根目录运行，保证相对路径指向同一数据库。

生成并设置密钥的示例，不使用示例固定值：

```powershell
$env:JWT_SECRET = .\.venv\Scripts\python.exe -c "import secrets; print(secrets.token_urlsafe(48))"
```

JWT 密钥只由后端需要，界面通过登录获取短期令牌。不要向审计报告或截图打印密钥。

## 7 实现后启动顺序

以下初始化与应用启动流程尚未完整实现；其中 `scripts.generate_data` 已在 A1 完成，其余脚本仍需按分工实现。本节不是当前可立即运行的完整应用说明。

初始化阶段由 B、A 依次完成，脚本应能安全重复运行或明确拒绝覆盖已有版本：

```powershell
.\.venv\Scripts\python.exe -m scripts.init_db
.\.venv\Scripts\python.exe -m scripts.seed_users
.\.venv\Scripts\python.exe -m scripts.generate_data
.\.venv\Scripts\python.exe -m scripts.train_model
```

启动时开三个终端，从同一代码根目录分别执行：

```powershell
# 终端一：API，演示环境使用单进程
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

```powershell
# 终端二：监测 worker
.\.venv\Scripts\python.exe -m app.worker
```

```powershell
# 终端三：演示界面
.\.venv\Scripts\python.exe -m streamlit run ui/app.py --server.address 127.0.0.1 --server.port 8501
```

检查顺序：打开 `http://127.0.0.1:8000/health` 确认 API 和数据库状态；打开 `/docs` 调试接口；打开 `http://127.0.0.1:8501` 登录；调用回放脚本输入合成请求；等待窗口闭合后查看指标。健康接口不能暴露密钥、绝对敏感路径或完整异常栈。

本地演示只绑定回环地址；远程部署需另行配置 HTTPS、访问控制和密钥管理，不直接将开发服务公开到互联网。

## 8 常见问题处理

- 模块找不到：确认用的是 `.venv` 中的解释器、依赖已安装、当前目录是代码根目录。
- SQLite 锁冲突：确认只有一个 worker，事务保持短小；检查图形工具是否持有写事务；配置超时并对锁冲突进行有界重试，不无限重试。
- 模型复现不一致：先核对包摘要、特征顺序、预处理、依赖和阈值；不要通过放宽阈值掩盖环境差异。
- 页面无指标：检查 worker 心跳、outbox 积压、窗口是否闭合、有效样本是否达标。
- 401/403：检查令牌有效期和后端授权；不通过在页面中改角色变量绕过。
- 演示前：备份数据与模型包，准备一份全新的合成演示库；不要删除原有证据库来“清场”。
