# A3 接口操作与交接

日期：2026 年 11 月 4 日。已实现评分接口、模型激活接口，以及评分记录、输入快照、初始审计证据和 outbox 的原子保存。这里的演示接口只使用合成数据，不开展真实信贷业务。

后续状态：A4 已于 2026 年 11 月 5 日完成，监测消费、指标、规则与告警操作见 [A4 运行与验收](A4-监测worker与验收.md)。下文的 A3 验收证据保留当时无消费者的检查条件。

## 1 当前边界

B 分支尚未交付数据库服务和 JWT/RBAC。为使 A3 可以独立验收，本次定义了 [PredictionStore 与 Authenticator 契约](../app/contracts.py)，并提供 [SQLite/SQLAlchemy 参考适配器](../app/storage/sqlite_store.py)和[演示令牌适配器](../app/demo_auth.py)。

这些适配器是后续 B 接入的参考，不代表已经完成 B 的用户数据库、登录、权限管理界面、审计导出或复现任务。A4 worker 尚未实现，事件处于 pending 状态。

## 2 已完成的接口

- `GET /health`：免登录，返回 API 和数据库是否可连接；不返回路径、凭据或异常栈。
- `GET /api/v1/model-versions`：按服务端配置的模型授权列出版本 UUID、包版本名、摘要、validated 状态与 active 标记。
- `POST /api/v1/model-versions/{version_id}/activate`：仅管理员，验证固定模型包后，原子更新激活指针、审计记录和幂等回执。
- `POST /api/v1/predictions`：要求 scorer 权限和模型授权；对明确的已激活版本评分并原子保存。
- `/docs`、`/openapi.json`：本地接口文档与模式。不要把当前开发服务公开到互联网。

本阶段模型通过 A2 的受控登记清单在启动时导入，没有实现任意用户上传和登记模型文件的 HTTP 能力。两个已交付版本的 UUID 可从版本列表查询，不能用包目录名替代 UUID 参数。

## 3 安装与启动

当前 `.venv` 已安装依赖，另一台匹配环境的电脑可执行：

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-a3.lock.txt
.\.venv\Scripts\python.exe -m pip check
```

模型加载仍要求 A2 的环境字段匹配，尤其是 Python 3.12.14 与固定的模型依赖；`py -3.12` 并不保证精确小版本，环境不匹配时按 A2 文档新建版本训练，不能绕过检查。

在仓库根目录的 PowerShell 终端一中生成临时令牌并启动服务：

```powershell
New-Item -ItemType Directory -Force -Path data/runtime | Out-Null
$taskCredentials = @{
    admin_token = (.\.venv\Scripts\python.exe -c "import secrets; print(secrets.token_urlsafe(48))")
    scorer_token = (.\.venv\Scripts\python.exe -c "import secrets; print(secrets.token_urlsafe(48))")
}
$taskCredentials | ConvertTo-Json | Set-Content -Encoding utf8 data/runtime/demo-credentials.json
$env:APP_ADMIN_TOKEN = $taskCredentials.admin_token
$env:APP_SCORER_TOKEN = $taskCredentials.scorer_token
$env:DATABASE_URL = 'sqlite:///./data/runtime/platform.db'
$env:ARTIFACT_ROOT = './artifacts'
$env:INFERENCE_TIMEOUT_MS = '2000'
.\.venv\Scripts\python.exe -m uvicorn app.main:create_app --factory --host 127.0.0.1 --port 8000
```

`data/runtime` 已被 Git 忽略。演示令牌是可访问本机服务的凭据，不上传、不截图公开；用完后关闭服务。两个令牌必须不同且至少 32 字符，不提供默认弱令牌。配置对象的 repr 不显示令牌。

`.env.example` 只说明变量名称；代码不自动读取 .env。缺少令牌时应用拒绝启动，而不是自动开放匿名访问。停止前台服务使用终端的 Ctrl+C。

## 4 激活与评分

另开终端二，仍位于仓库根目录；令牌从本机私有文件读取，不需要粘贴到聊天：

```powershell
$taskCredentials = Get-Content -Raw data/runtime/demo-credentials.json | ConvertFrom-Json
$taskAdminHeaders = @{
    Authorization = "Bearer $($taskCredentials.admin_token)"
    'Idempotency-Key' = 'manual-activate-v1'
}
$taskVersions = Invoke-RestMethod -Uri http://127.0.0.1:8000/api/v1/model-versions -Headers $taskAdminHeaders
$taskVersion = $taskVersions.items | Where-Object { $_.version -eq 'credit-logreg-v1' }
Invoke-RestMethod -Method Post -Uri "http://127.0.0.1:8000/api/v1/model-versions/$($taskVersion.model_version_id)/activate" -Headers $taskAdminHeaders

$taskRequest = Get-Content -Raw examples/A3-score-request.json | ConvertFrom-Json
$taskRequest.model_version_id = $taskVersion.model_version_id
$taskBody = $taskRequest | ConvertTo-Json -Depth 20
$taskScorerHeaders = @{
    Authorization = "Bearer $($taskCredentials.scorer_token)"
    'Idempotency-Key' = 'manual-score-001'
}
Invoke-RestMethod -Method Post -Uri http://127.0.0.1:8000/api/v1/predictions -Headers $taskScorerHeaders -ContentType 'application/json; charset=utf-8' -Body $taskBody
```

评分成功首次返回 HTTP 201，包含 prediction_id、snapshot_id、event_id、固定版本、概率、阈值、解释快照、UTC 时间和实际推理耗时。输入样例见 [A3-score-request.json](../examples/A3-score-request.json)。

原始输入与规范化输入分开存储；月收入和贷款额额外按整数分保存。缺失值保留为 null，不用填补后的完整矩阵冒充原始数据。

## 5 幂等与错误语义

所有 POST 必须携带 1—128 字符的 `Idempotency-Key`，仅允许字母、数字、点、下划线、冒号和连字符。

- 同一主体、同一接口、同一键且相同内容：返回原 HTTP 状态和原响应体，响应头 `Idempotency-Replayed: true`。
- JSON 对象键顺序不影响摘要。数值表示、字符串内容、显式 null 与省略字段等原始内容差异会影响摘要；不要用同一个键提交修改后的请求。
- 同键异内容返回 409；不同主体使用同一键互不串记录。
- 顺序重复请求不会重复推理。并发请求可能各自执行推理，但只有一个终态记录、快照、审计和事件被提交；不宣称计算执行恰好一次。
- 切换到 v2 后，新 v1 请求返回 409；已提交的 v1 同键请求仍返回原结果。受理时已固定版本的在途请求允许按原版本完成，不中途混用新模型。
- 无令牌 401、角色或模型范围不足 403、版本不存在 404、状态或幂等冲突 409、格式错误 422。

模型错误返回 503，但与“存储未提交”有明确区别：

- `MODEL_PACKAGE_UNAVAILABLE` / `MODEL_ENVIRONMENT_MISMATCH`：保存 failed 记录与 outbox，概率和判断为 null，`inference_attempted=false`、`inference_ms=null`。
- `INFERENCE_FAILED` / `INFERENCE_TIMEOUT`：保存 failed 记录，概率为 null，保留实际推理尝试标记和耗时。
- `STORAGE_UNAVAILABLE`：整个事务回滚，响应不包含伪造的评分编号；使用相同键重试。

已经保存的失败记录同样幂等；模型恢复后若要重新计算，使用新键。`INFERENCE_TIMEOUT_MS` 是同步调用返回后的软时限检查，不会强行中断卡死的 C 扩展；严格硬超时需要后续进程隔离。

## 6 事务与 outbox 约定

模型加载和推理在写事务外；保存时使用 SQLite `BEGIN IMMEDIATE` 形成短写事务，事务内再核对幂等记录。四次逻辑写入按顺序为：input_snapshots、predictions、audit_logs、outbox_events。提交成功后才响应。

在上述任意阶段故障均全部回滚。模型激活的指针、审计与幂等回执也在同一事务。SQLite 启用 WAL、外键和五秒锁等待；锁错误返回可重试的存储失败，不进行无限等待。

初始审计事件为 prediction.completed，不记录 bearer token 或完整敏感输入。完整原始输入只存输入快照。

outbox 使用 schema_version=1.1，在原协议上增加 `inference_attempted` 和 `error_code`；事件不复制完整输入，通过 snapshot_id 关联。加载阶段失败不是推理失败率的分母成员，A4 必须用该标记区分。

当前两个版本的“active”由 model_activations 指针决定。版本元数据保持 validated；只切换指针，不覆盖历史版本。这与“用 status 就地改写旧版本”的实现不同，B 合并时应保留该语义或提供兼容映射。

- 真实 HTTP 验证保存三个评分（两成功、一失败）、三个快照、三个 pending 事件和五条审计（含两次激活），与重复/冲突请求数量核对一致。
- 两个 A2 模型包没有改写；评分函数仅增加可选计时输出参数，既有确定性返回值和历史样例保持一致。训练配置中的源码摘要表示训练当时的来源。

复验命令：

```powershell
.\.venv\Scripts\python.exe -m scripts.verify_a3_http
.\.venv\Scripts\python.exe -m scripts.run_acceptance
```

HTTP 验证脚本启动隐藏的临时回环服务，生成临时令牌和 SQLite 数据库，结束时关闭服务并清理目录。它只对临时复制的模型包注入故障，不移动项目原模型文件。

当前锁定的 Starlette 使用 httpx 兼容测试接口时会给出弃用提示，现有验证通过。后续升级应整体检查测试客户端组合，不能为消除提示随意改变 A2 的模型依赖。
