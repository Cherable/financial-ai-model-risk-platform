# 项目范围与课程交付

## 1 项目定位

项目名称：金融 AI 模型风险监测与审计平台。

目标是回答三个具体问题：模型接入后的输入和运行情况是否异常；某次评分使用了什么模型和输入；风险发生后由谁处理、如何形成可追溯记录。平台提供风险管理依据，不把数据漂移直接判定为模型失效，也不替代信贷审批。

业务场景固定为模拟个人信贷评分。模型输出 `risk_probability`，表示在本模拟任务定义下的风险概率；界面必须标注“合成数据演示”，不能称其为经过真实业务校准的违约概率。

## 2 用户与权限

- 模型开发人员：登记模型和版本，查看自己获授权的模型元数据、指标及解释信息。
- 风险管理人员：查看指标，配置获授权模型的预警规则，认领与关闭告警。
- 审计人员：查询授权范围内的评分证据，申请或执行复现，导出审计报告；不修改原始评分记录。
- 管理员：管理用户与模型访问权限，执行版本激活等受控操作；所有关键操作写入审计日志。

两位开发成员是开发分工，以上四类是系统角色，不要求四个人操作。演示时使用四个独立测试账号切换。

## 3 基础版功能

### 模型登记与评分留痕

登记一个模型的两个版本，每个版本保存模型文件、预处理流程、特征顺序、文件摘要、训练配置、解释基线、依赖锁文件与决策阈值。通过模拟评分接口提交输入，并保存输入快照、输出、耗时、状态、版本和关联编号。

只允许选择服务器预置模型文件的受控引用，不允许用户上传任意 pickle/joblib 文件后执行加载。

### 风险监测与告警

基础版监测：特征缺失率、特征分布漂移、预测分布变化、成功请求推理耗时、推理失败率。采用固定非重叠窗口，后台计算后显示数据量和窗口范围。

每条告警必须关联模型版本、指标、规则版本、窗口、触发值和阈值。风险人员填写认领和处置结论，形成可回看的闭环。

### 决策追溯与复现

通过 `prediction_id` 查看输入、评分、模型和解释；使用同一模型包、依赖环境和输入重新推理，与原结果比较。缺少模型文件、摘要不匹配或依赖不兼容时，明确显示复现失败原因，禁止用当前模型替代历史模型。

### 审计与访问控制

后端检查角色与模型访问范围；记录规则修改、告警操作、模型激活、敏感详情查询、复现和导出。导出采用 JSON 或 CSV，包含来源记录编号和生成时间。

## 4 扩展与排除范围

可选扩展按顺序为：真实标签回流后的效果监测、简单模型版本对比、PostgreSQL 迁移、Docker Compose 演示部署。

基础版不做分布式消息集群、全自动模型训练与上线、多租户计费、银行生产接入、跨机构数据共享或生成式 AI。高并发、高可用、不可篡改审计均不能仅靠本原型宣称已经实现。

## 5 数据方案

A 使用固定随机种子生成合成数据，字段包括年龄、月收入、负债收入比、历史逾期次数、贷款金额和就业年限，用户以虚构编号表示。年龄只用于教学特征演示，其真实业务使用的公平性和适当性不在原型验证范围内。

建议准备：

- 训练集 5,000 条：生成模拟标签，仅用于训练；预处理在训练集上拟合。
- 留出测试集 1,000 条：使用不同种子，不参与拟合和阈值调优；评估结果必须标注为合成数据结果。
- 参考样本 1,000 条：用于固定版本的监测分箱和参考分布，不作为训练数据的替代评估集。
- 正常评分流 1,000 条：演示正常窗口。
- 漂移评分流 1,000 条：明确调整收入或负债率分布；不把漂移等同于性能下降。
- 缺失样本流 1,000 条：对一个字段注入约 10% 缺失，验证统计与告警。
- 故障场景：通过测试配置注入推理超时或不可用状态，不通过损坏源文件制造故障。

分布、标签生成公式和种子需写入数据说明。公开数据集若后续引入，应补充来源、许可与字段说明。

## 6 课程提交清单

必须准备的材料：

1. 软件需求规格说明：背景、角色、边界、功能、输入处理输出、异常、质量属性与环境约束。
2. 数据流图：上下文图和一级数据流图；数据流、处理与存储编号互相对应。
3. 数据字典：字段类型、含义、单位、范围、可空性、来源和去向。
4. ASR 列表：场景、响应目标、设计决策与验证方式。
5. 五类架构图：业务、数据、逻辑、技术、部署；逐图说明职责与关系。
6. 实验报告：按原 Word 模板整理，保留双人分工、交叉检查和实际完成情况。

可运行原型、接口截图和测试记录作为加强交付。若没有编码，验证部分应写“设计走查/计划”，不得写成“测试通过”。

## 7 时间安排

八个实验学时优先用于课程设计材料：

- 学时 1—2：共同确定范围和核心用例；A 整理监测需求，B 整理审计与权限需求。
- 学时 3—4：共同核对数据流和数据字典，形成需求说明初稿。
- 学时 5—6：分别完成负责的架构图和 ASR，交叉检查。
- 学时 7—8：走查五个案例，统一图表，整理报告与答辩分工。

如另做原型，建议两人各预留约 18—28 小时课外时间；该数值是计划估计，取决于 Python 和接口开发熟练程度：

- 第 1 阶段：环境、模型样例、数据结构与契约。
- 第 2 阶段：评分保存、持久化事件、监测和审计查询。
- 第 3 阶段：权限、复现、告警处置与界面。
- 第 4 阶段：异常验证、演示准备和报告修订。

时间不足时依次减少容器化、标签回流、复杂图表；保留评分留痕、一个监测指标、一个告警处置流程和一次历史复现。
